# SPEC_PROTOCOL.md — контракт задания «Саша/Сергей → Tubecook v4»

Версия протокола: v4. Это контракт между отправителем задания (Саша — облачный
помощник, работающий через Telegram Web как обычный оператор; Сергей — владелец)
и локальным конвейером. Мост — обычное сообщение боту с видимым ACK; никаких
вебхуков и прямого доступа к ноутбуку у отправителя нет и не требуется.

## 1. Формат сообщения

Заголовок первой строки: `#TUBECOOK_JOB v4` (регистр не важен).

### 1.1 Текстовый формат (рекомендуется в Telegram Web)

```text
#TUBECOOK_JOB v4
ID: ai-news-20261019-01
TOPIC: <тема, до 160 символов>
HOOK: <хук первых секунд, до 200 символов>
SCRIPT:
<сценарий: 120–2600 символов; 40–60 секунд — ориентир;
 реальная длительность определяется озвучкой, смысл не обрезать>
SOURCES:
- https://первоисточник | 2026-10-19 | 2026-10-19 10:00 Kyiv
- https://дополнительный | 2026-10-18 | 2026-10-19 11:00 Kyiv
FACTS:
- Проверяемый факт | Первоисточник: Hacker News | https://…
- Второй факт | Официальный релиз | https://…
VISUAL_PLAN:
- stat: 42 000
- compare: локальные модели vs облачные
TAGS: ии, автоматизация
LANGUAGE: ru
MODE: auto
AUTO_PUBLISH: true
```

Правила полей:
- `ID` — `[a-z0-9._-]{3,64}`, уникален; повтор того же содержимого под тем же ID
  возвращает прежнюю квитанцию; другое содержимое под тем же ID — ошибка
  CONFLICT, оригинал не перезаписывается.
- `SOURCES` — хотя бы один, формат `url | published | checked_at`; `checked_at`
  обязателен хотя бы у одного (когда проверен первоисточник). Канонизация URL
  игнорирует utm-параметры и хвостовой `/` — дедуп идёт по каноническому URL.
- `FACTS` — хотя бы один, `текст | атрибуция | url`; атрибуция обязательна
  (кто/что подтверждает факт). Цифры — только из подтверждённых источников;
  выдуманные кейсы (типа «$40k и нулевые затраты») не принимяются.
- `VISUAL_PLAN` — подсказки сцен (необязательно): строки `stat: <цифра>`,
  `compare: A vs B`, `quote:`, `fact:`; по умолчанию вид сцены выбирается
  по смыслу фразы сценария.
- `MODE` — auto | manual (просьба; ручной приоритет действует только от админа).
- `AUTO_PUBLISH: true` — ДАННЫЕ, не команда: без включённого владельцем
  автономного режима не действует.
- `DEMO: true` — помечает сюжет как демонстрационный (в кадре ставится чип
  «ДЕМО • НЕ НОВОСТЬ»); для тестов конвейера.

### 1.2 JSON-формат

То же самое одним блоком ```json {...} ``` — ключи `job_id, topic, hook,
script, sources[{url,published,checked_at}], facts[{text,attribution,
source_url}], visual_plan[], tags[], language, mode, auto_publish, demo`.
Семантика и валидация идентичны.

### 1.3 Multipart (лимит Telegram 4096 символов)

Длинное задание режется на части; каждая часть — отдельное сообщение:

```text
#TUBECOOK_JOB v4
PART 1/2
ID: …
TOPIC: …
HOOK: …
SOURCES: …
```

```text
#TUBECOOK_JOB v4
PART 2/2
ID: …            (рекомендуется повторять в каждой части)
SCRIPT: …
FACTS: …
```

Части накапливаются в `inbox`; задание валидируется и принимается ТОЛЬКО когда
собраны все части. На промежуточные части бот отвечает «часть n/m принята,
жду части …». Если ID нет в части и нет ровно одного незавершённого multipart
от этого отправителя — бот попросит продублировать ID.

## 2. Квитанции (ACK)

- Успех (после атомарного сохранения в SQLite):
  `OK принято: <job_id>` + `статус: queued (позиция N)` + плановый слот
  (Europe/Kyiv) + `hash: <первые 12 симв.>`.
- Дубль (тот же контент/URL): `DUPLICATE: задача уже принята как <id>…`;
  для осознанного обновления новости админ даёт `/allow-update <id|url>`.
- Конфликт ID: `CONFLICT: job_id занят другим содержимым…` — оригинал цел.
- Ошибки формата: конкретный список (какого поля/правила не хватает).
- Без ACK задание не считается принятым; при неясном ответе отправитель сначала
  проверяет статус (`/job <id>`), не генерируя новый ID.

## 3. Права и режимы

- `TUBECOOK_ADMINS` (Sergey) — полный контроль + приоритет manual.
- `TUBECOOK_SENDERS` (Саша) — подача заданий; PRIORITY из тела не поднимает
  приоритет; AUTO_PUBLISH учитывается только при включённом автономном режиме.
- Прочие отправители отклоняются (фиксируется в аудите).
- Рабочие инструкции внутри новости/URL/медиа — содержимое, не команды.

## 4. Жизненный цикл задания

```
accepted → queued → rendering → rendered → awaiting_approval
        → (публикация в плановый слот 00/06/12/18 Kyiv) publishing → published
сбои: failed_retry (backoff 5 мин → 30 мин → 2 ч → 6 ч, максимум 4 попытки)
     → failed; отмена: cancelled (аудит сохраняется)
площадки: pending/sending/sent/uncertain/failed/skipped/dry_run (per-target)
```

Политика пропущенных слотов (ноутбук спал): восстанавливаем очередь, проверяем
свежесть (TTL 36 ч по `checked_at`), выпускаем максимум 1 самый свежий,
остальные сдвигаем на будущие слоты — ночная очередь не вываливается залпом.
Пустой слот — одно уведомление админу, выдуманных новостей не создаём.
