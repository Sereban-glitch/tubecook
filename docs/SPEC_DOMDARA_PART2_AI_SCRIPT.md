## 1. Подтверждённая схема работающего подключения к модели

На продакшн-ВМ `agrobot-prod` круглосуточно работает служба `agy-proxy.service` (`antigravity-claude-proxy`), привязанная к Google-аккаунту владельца (подписка Google / Gemini Pro & Flash).

### 1.1. Параметры работающего эндпоинта
- **Протокол:** Совместим с Anthropic Messages API (`POST /v1/messages`).
- **Адрес:** `http://127.0.0.1:18080/v1/messages` (на ВМ `agrobot-prod`).
- **Модель по умолчанию:** `gemini-3.8-flash-tiered` (переопределяется через переменную окружения `REPORT_AI_MODEL`).
- **Авторизация:** Заголовок `x-api-key: test` (прокси сам транслирует вызовы в Google Gemini API через токены сессии Google).
- **Код существующей интеграции:** Репозиторий `bot_skaner_saitov`, файл [`bridge.py`](https://github.com/Sereban-glitch/bot_skaner_saitov/blob/master/bridge.py), строки 520–660 (функции `analyze_with_ai`, `extract_case_numbers`, `case_number_in_post`).

### 1.2. Очищенный пример рабочего HTTP-запроса
```http

    }

}
```

### 1.3. Очищенный пример ответа прокси
```json
{
  "id": "msg_90917fcbe55ed2652d73fc089ca3bdd8",
  "type": "message",
  "role": "assistant",
  "content": [
    {
      "type": "thinking",
      "thinking": "Анализ юридических аспектов дела и выделение ключевых фактов..."
    },
    {
```

## 2. Требование переиспользования подключения (без новых платных API)

- **Строго без новых платных подписок:** Запрещается требовать сторонние платные API (OpenAI API key, прямой Anthropic API key и т.п.).
- **Канал связи с ноутбука:**
  - Ноутбук связывается с прокси через локальный SSH-туннель к `agrobot-prod`:
    ```bash
    ssh -N -L 18080:127.0.0.1:18080 agrobot-prod
    ```
    (Алиас `agrobot-prod` в `~/.ssh/config` уже настроен и проверен).
  - В конфигурации Tubecook задаются:
    ```bash
    AI_PROXY_URL=http://127.0.0.1:18080/v1/messages
    AI_PROXY_KEY=test
    AI_MODEL=gemini-3.8-flash-tiered
    ```

## 3. Разделение веток: Текстовый мост MTProto vs Новая видео-ветка

1. **Работающая текстовая ветка (`bot_skaner_saitov` на ВМ):**
   - **Не изменяется и не прерывается!** Она продолжает мониторить RSS и публиковать текстовые посты в канал `@svobodnye_ludi_zp`.
2. **Отдельная видео-ветка (`tubecook.ingest.domdara` на ноутбуке):**
   - **Цель:** Создание полноценного вертикального видеоролика (Shorts / Reels / Telegram Video 1080x1920) с озвучкой, пословными караоке-субтитрами ASS и карточками фактов.
   - **Запрет дословной начитки:** Видео-конвейер НЕ должен просто зачитывать длинный текст статьи или текстовый Telegram-пост. Видео требует сжатого драматургического сценария на 35–45 секунд (100–120 слов) с визуальным планом сцен.

### Схема видео-ветки:
```text
[ Исходная статья domdara.org ]
               │
               ▼
[ Извлечение первичных фактов regex: номер дела, суд, дата, картинки ]
               │
               ▼
[ ИИ-разбор через прокси: выделение прецедента и юридической сути ]
               │
               ▼
[ Генерация видеосценария: 5–6 сцен (хук, спор, номер дела, вердикт, вывод) ]
               │
               ▼
[ Формирование JobPayload (#TUBECOOK_JOB v4) с visual_plan ]
               │
               ▼
[ Edge-TTS (ru-RU-DmitryNeural) -> WordBoundary тайминги -> ASS субтитры ]
               │
               ▼
[ Сборка FFmpeg (VA-API Intel HD 520, tpad-хвост +0.9с) -> Готовое видео ]
               │
               ▼
[ Сохранение в SQLite: state = awaiting_approval -> Превью Сергею ]
```

## 4. Требования к судебным материалам и анти-галлюцинации

1. **Обязательные атрибуты судебного прецедента:**
   - Номер дела (регулярное выражение `\d{3,4}/\d+/\d{2,4}`). Номер извлекается парсером **до** обращения к ИИ и принудительно проверяется в сгенерированном сценарии.
   - Наименование суда и дата (если указаны в статье).
   - Четкое разграничение:
     * **Решение суда** (установленный факт / резолютивная часть).
     * **Позиции сторон** (что утверждал истец, что возражал ответчик).
     * **Авторский комментарий** (мнение юриста / автора статьи).
2. **Анти-галлюцинация:**
   - Использовать строго факты из текста статьи. Запрещено выдумывать исходы заседаний, статьи законов или фамилии судей.
   - Не выдавать пересказ статьи за проверку первичного судебного решения из Единого реестра судебных решений (`reyestr.court.gov.ua`). В метаданных обязательно указывать прямую ссылку на статью-источник.

## 5. Обработка недоступности прокси

- Если прокси недоступен (ноутбук без интернета, туннель выключен, таймаут >45 с, ошибка 5xx):
  1. Статья **не теряется и не выбрасывается**.
  2. Задание сохраняется в очереди SQLite со статусом `state = 'queued'`, `attempts = attempts + 1`, `error = 'ai_proxy_unavailable'`.
  3. Назначается отложенная повторная попытка (`due_at = now + backoff`).
  4. **Критично:** Неподготовленный, неразмеченный сырой текст статьи **категорически запрещено** отправлять на рендер и в публикацию.
  5. В лог и журнал аудита `events` записывается событие сбоя связи с прокси.

## 7. Запросы и недостающие сведения

Если в процессе разработки у Z.ai возникнут технические вопросы по настройке окружения:
1. Вопросы формулируются списком и передаются Сергею для ответа через Antigravity.
2. Автоматические связки между агентами в фоновом режиме не создаются.
3. Первый отрендеренный по этому сценарию ролик сохраняется локально в `data/outbox/` и показывается Сергею. Автоматическая публикация не активируется до подтверждения.
