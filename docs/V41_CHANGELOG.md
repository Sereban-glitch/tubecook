# Changelog v4.1 — ответы на обратную связь по первому ролику

Дата: 2026-10-19. База: коммит `614d99f` (92 теста, первый ролик «Водоканал»).
Результат итерации: **128/128 тестов зелёные** (92 сохранены без изменения
семантики + 36 новых), контрольный рендер — ниже.

## 1. Фоновая музыка (замена «мрачного» soft_loop)

- **Три нейтральные подложки** сгенерированы процедурно (`scripts/make_bgm.py`,
  numpy, детерминированно, без внешних сэмплов — права чистые):
  - `news_loop.mp3` — тёплый пад A-мажор (I–vi–IV–V), арп-пульс восьмыми,
    мягкий пульс на 1 и 3 доли, 96 BPM (**новый дефолт**);
  - `legal_loop.mp3` — спокойный D-мажор без пульса, разреженные ноты, 84 BPM;
  - `tech_loop.mp3` — лидийский пад, синкопированный арп, 108 BPM.
  Все: ~32 c, целое число тактов (беззапаучный луп), пик −12 dBFS.
- **Выбор по категории/пути/выключение**: `TUBECOOK_BGM=news|legal|tech|
  legacy|none|<путь>` (config.py: `BGM_CATEGORIES`, `_resolve_bgm`);
  `legacy` — старый трек для A/B-сравнения. Категория попадает в
  `render_report.json` (`bgm.category/track/volume`).
- **Баланс даккинга** (`render._render_audio`): BGM получает `highpass=f=180`
  (не мутит частоты диктора), bed-громкость `TUBECOOK_BGM_VOLUME`
  (0.0..1.5, дефолт 0.5), `sidechaincompress threshold=0.02 ratio=12
  attack=8 release=280` (музыка ныряет на ~12+ dB во время речи и мягко
  всплывает в паузах), `amix normalize=0` (голос не ослабляется).
  Замер контрольного рендера: микс −16.0 LUFS, музыка в паузе −31.3 дБ
  (mean), речь mean −18 дБ — голос кристально чистый, подложка лёгкая.

## 2. Типографика субтитров и просвечивание при xfade

- **Строки-ряды вместо переносов libass** (`ass._pack_rows`): ширина каждого
  ряда меряется PIL (DejaVu Bold 64px) и ограничена 940 px → libass никогда
  не переносит строку → вертикальные наложения букв при переносе исключены
  **по построению**. Каждый ряд — отдельное событие с фиксированной позицией
  `\an5\pos(540,1458)` и мягким pop-масштабом `\t(0,140,\fscx100\fscy100)`.
- **Сброс строки по границам предложений и паузам**: слова двух предложений
  никогда не попадают в один ряд — границы те же, что у сцен
  (`scenes.sentence_word_spans`, единая точка выравнивания); пауза ≥ 0.35 c
  тоже сбрасывает строку. Склейки «конец фразы + начало следующей» больше нет.
- **Переходы без текста**: кроссфейды собираются из коротких фоновых клипов
  **без карточек** (`_bgonly_filter_graph`/`_transition_cmd`) — уходящий
  текст физически не может просвечивать сквозь входящий; карточка в теле
  сцены дополнительно гаснет к его концу (`fade alpha=1`), финальная сцена
  держит карточку до стоп-кадра.
- Бонус: фикс сопоставления `visual_plan`, индексированного по сценам
  (как в `job_domdara_vodokanal.json`): раньше body-фразы смещались на −1
  и вторая сцена получала вид `hook`, а «Номер дела в описании» — `outro`.

## 3. Motion Design (кинетика вместо слайд-шоу)

- **Кинетическая типографика**: номер дела «ДЕЛО № 280/8165/23» (и ключевые
  цифры stat-сцен) появляются pop scale-up 78% → 108% → 100% (overshoot)
  на тёмной плашке (ASS `Kinetic`, BorderStyle=3).
- **Анимированные бейджи** («СТОРОНЫ СПОРА», «РЕШЕНИЕ СУДА»,
  «ПРАКТИЧЕСКИЙ ВЫВОД», «ФАКТ N», …): плавный въезд слева `\move` +
  scale-settle, непрозрачная основа-плашка.
- **Полоска прогресса выпуска**: тонкий трек + акцентный fill шагом 0.5 c
  (векторная графика libass `\p1`), заполняется ровно по таймлайну
  (проверено по кадрам: 11% / 40% / 50% / 94% на 6.4/23/29/54 c).
- **Юридические шаблоны карточек** (gfx.py): `case` — карточка дела
  (номер крупно со свечением + суд + детали), `verdict` — тезисы с
  акцентными галочками, `problem` — фото в скруглённой рамке с подписью
  (поддержан `image_url` из `visual_plan`), `practical_value` — нумерованные
  шаги. Сцены носят `badge/kinetic/case_number/points/subtitle/image`.

## 4. Память рендера (входит в ограничение HP ≤ 1.5 ГБ)

Прежняя однопроходная xfade-цепочка на 12 входов держала очереди кадров
всех сцен (замер песочницы: пик **1835 МиБ**). Новая трёхпроходная схема
(`_render_video`): тела сцен → короткие переходы из пары клипов →
concat-demuxer (copy, один видео-вход) + субтитры + энкод. Пик
контрольного рендера: **826 МиБ** (−55%), в допуске HP даже для CPU-режима.

## 5. Проверки (что реально сделано, без прикрас)

- `python3 -m pytest`: **128 passed** (92 прежних + 36 новых:
  `test_bgm.py` — ассеты/детерминизм синтеза/категории конфига/clamp
  громкости/граф даккинга/выключение BGM; `test_ass_motion.py` —
  отсутствие склейки предложений, сброс по паузе, ширина рядов,
  последовательность и покрытие, прогресс-бар, кинетика/бейджи/приоритеты;
  `test_motion_design.py` — юридические виды сцен из планов обеих
  конвенций, извлечение номера дела/пунктов/фото, карточки 1080x1920,
  правила фейдов и безкарточность переходов).
- Контрольный рендер `examples/job_domdara_vodokanal.json` с **реальной
  озвучкой Edge-TTS** (`tts_engine: edge`): 57.4 c, 11 сцен + переходы,
  дельта аудио/видео 40 мс, `assert_tail` пройден, пик RAM 826 МиБ,
  интегрированная громкость −16.0 LUFS.
- Визуальная проверка кадров (VLM + пиксельные пробы): прогресс-бар
  заполнен по таймлайну; бейджи/кинетика читаются точно («СТОРОНЫ СПОРА»,
  «ДЕЛО № 280/8165/23», «РЕШЕНИЕ СУДА», «ПРАКТИЧЕСКИЙ ВЫВОД»); караоке-ряды
  без наложений, активное слово подсвечено; переход без карточного текста
  (0 циановых пикселей в зоне чипа); карточки юршаблонов с фото, номером
  дела, галочками и шагами — на месте.
- Чего НЕ проверялось: VA-API-путь на реальном железе HD 520 (в песочнице
  нет устройства — финальный энкод CPU; для VA-API changed только вход
  графа — см. `fmt=hwupload`, как раньше), live-публикация по-прежнему
  dry-run, слуховое прослушивание подложки остаётся за владельцем.

```bash
# категории: news | legal | tech | legacy | none; громкость TUBECOOK_BGM_VOLUME=0.5
```
